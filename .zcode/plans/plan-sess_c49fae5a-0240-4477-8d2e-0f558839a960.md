# pkg/ 模块化重构：一层嵌一层的分包

## Context

`pkg/engine` 已经长成 28 文件 3207 行的大杂烩：编排状态机、K8s Job 机器、脚本生成、日志协议、deploy 控制器、取消注册表、cron、IM 通知全部挤在一个 package 里，靠文件名区分领域。api（12 文件）里也混着纯 webhook 签名逻辑。用户要求把 pkg/ 改成分层嵌套的模块化结构。

**硬约束**：纯结构重构，行为零变化。路由、端点、验收脚本（test-mvp*.sh/smoke.js 只打 HTTP）全部不动；全部测试（含依赖包级 var 的测试 seam：`pollInterval`/`rolloutWaitTimeout`/`envResolver`/`sendNotify`/`notifyHTTP`）必须保持可写性。

## 目标结构（依赖全部单向向下，无环）

```
pkg/
├── config/            # 不动（leaf）
├── models/            # 不动（leaf）＋ 新增 ManualExec.Satisfied() 方法（从 engine/cancel.go 吸收 ApprovalSatisfied）
├── repo/              # 不动（mongo 持久层）
├── step/              # 【新包】脚本执行层（对照 Zadig jobexecutor+stepcontroller；只 import models）

│   ├── stepctl.go     ← engine/stepctl.go（newStepCtl 包内私有不变）

├── k8s/               # 【新包】K8s 访问层（import config+models，不碰 repo/engine）
│   ├── client.go      ← engine/k8s.go（NewClient）
│   ├── build.go       ← engine/job.go（JobName/BuildJob 导出；jobNeedsRunner 等包内私有）
```

无环证明要点：`engine/cron → engine`（cronTick 调 TriggerWorkflow）且 engine 不 import cron（main.go 直调 Start）；`engine ↔ engine/exec` 单向（engine→exec）；`engine/exec → engine/cancel` 单向；`step`/`k8s` 不 import 任何 engine*。

## 关键机械变换

1. **engine/exec 的接口签名**（唯一动逻辑形状的地方）：
   - 新 `exec.Ctx{Client kubernetes.Interface; NS string; Task *models.WorkflowTask; Mu *sync.Mutex; CancelCh <-chan struct{}}` 替代 `*taskCtx` 参数。
   - jobctl/deployctl 内 `tc.mu`→`c.Mu`、`tc.client`→`c.Client`、`tc.ns`→`c.NS`、`tc.t`→`c.Task`、`tc.cancelCh`→`c.CancelCh`；`ack(tc.t)`→包内私有 `ackTask(c.Task)`（同款 repo.UpdateTask+日志，行为等价）。
   - run.go 的 runJobTask 构造 `&exec.Ctx{Client: tc.client, NS: tc.ns, Task: t, Mu: &tc.mu, CancelCh: tc.cancelCh}` 传入 `ctl.Run/SaveInfo/Clean` —— 同一把 mutex 指针，锁纪律注释原样保留。
   - `jobTimeout` const 与 `pollInterval` var 移入 exec/k8s.go（run.go 自身不用它们；deployctl_test 的 fastPoll seam 原样可用）。

2. **导出改名**（全编译期可查）：
   - cancel：`registerCancel→Register`、`CancelRequested→Request`、`cancelled(ch)→Fired`、`errCancelled→ErrCancelled`、`CancelTree→Tree`；`ApprovalSatisfied` 整体迁为 `models.(*ManualExec).Satisfied()`（api/approve.go 改调方法）。
   - step：`applyStepBanners→ApplyStepBanners`、`sliceStepLogs→SliceStepLogs`、`finalizeSteps→FinalizeSteps`、`podLog→k8s.PodLog`。
   - k8s：`jobName→JobName`、`buildJob→BuildJob`、`podExitInfo→PodExitInfo`、`deleteOpts→DeleteOpts`。
   - notify：`notifyOnFinish→NotifyOnFinish`；cron：`MatchCrontab→Match`、`StartCronScheduler→Start`。

3. **import 更新**：main.go（cron.Start）、api 全部 handler（engine.X→k8s.X/cancel.X/cron.X/webhook.X/models 方法）、engine 核心七文件。api/webhook.go 拆两半：纯逻辑（gitPushPayload/signatureOf/signatureValid/isPushEvent/branchOfRef/normRepo/repoMatches）进 pkg/webhook，handler 留 api 调 `webhook.Match(...)` + `engine.TriggerWorkflow`。

4. **测试随迁与拆分**：jobctl_test.go 三拆（TestJobName→k8s、TestResetForRetry→exec、TestIgnorePolicyBrake→engine/core_test.go）；api/artifact_test.go 里 ArchiveCtl 生成断言迁到 step 包；api/webhook_test.go 签名部分迁 webhook 包。所有改包级 var 的测试 seam 随文件同包迁移，seam 机制不变。

5. **注释里的路径/包名引用**（如"见 engine/logs.go"）随迁更新；AGENTS.md §2 代码结构段重写为新树。

## 关键文件清单

改：`pkg/engine/{run,task,trigger,queue,recover}.go`、`pkg/api/*.go`（import 面）、`main.go`、`AGENTS.md`
移+改：engine 的 driver/stepctl/logs/job/jobctl/deployctl/cancel/cron/notify(.go+test)
新：`pkg/step`、`pkg/k8s`、`pkg/webhook`、`pkg/engine/{cancel,exec,notify,cron}` 的包声明文件
不动：`pkg/models/*`（加一个方法）、`pkg/repo/*`、`pkg/config/*`、`deploy/*` 全部

## 验证

1. `go build ./... && go vet ./... && go test ./pkg/... -count=1`（mongo 相关测试自动 skip，需 port-forward 时拉起）
2. 单测全绿后本机引擎活体：port-forward + `MONGO_URI=… K8S_CONTEXT=k3s-heyuan HTTP_ADDR=":8080" go run .`，跑 `bash deploy/test-mvp1.sh`（变量/重试/取消/队列全链）+ `bash deploy/test-mvp3.sh`（cron/webhook/审批/release）——这两套对编排层改动最敏感
3. `deploy/build-push.sh 0.6.4` + helm upgrade → 集群侧 `MP_ROLE_LIVE=1 MP_BASE=https://… bash deploy/test-mvp2.sh`（exec/deploy 子包活体）+ `bash deploy/test-mvp4.sh`（含新 node --check 语法门）+ jsdom 冒烟
4. Git 流：`feat/pkg-restructure` 单分支单 PR，conventional commit，GitHub 侧合并

## 风险与止损

唯一动逻辑形状的是 exec 接口签名变换；锁纪律靠 Mu 指针同一性保住，取消 sentinel 靠 errors.Is 链路保留。若活体验证出红且 40 分钟内定位不了，回退该子域的拆分（exec 回 engine 主体）保 step/k8s/cancel/notify/cron 五包落地——分层收益的大头不受影响。
